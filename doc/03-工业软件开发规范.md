## 第一部分：代码规范

### 1.1 命名规范

#### C++命名规范（Google C++ Style Guide）

```cpp
// 类名：大驼峰（PascalCase）
class RecipeManager { };
class TcpWorker { };
class MesGateway { };

// 函数名：小驼峰（camelCase）
void loadRecipe();
bool isConnected();
int getRecipeCount();

// 变量名：小驼峰 + 下划线后缀（成员变量）
class Device {
private:
    std::string name_;           // 成员变量：下划线后缀
    bool isOnline_;
    int connectionCount_;

public:
    void setName(const std::string& name) {  // 参数：小驼峰
        name_ = name;
    }
};

// 常量：k前缀 + 大驼峰
const int kMaxConnections = 100;
const double kDefaultTimeout = 30.0;

// 宏：全大写 + 下划线
#define MAX_BUFFER_SIZE 4096
#define PROTOCOL_MAGIC 0x53454D49

// 命名空间：全小写
namespace semiconductor {
namespace gateway {
    class MesGateway { };
}
}

// 枚举：大驼峰（类型） + 大驼峰（值）
enum class DeviceState {
    Idle,
    Running,
    Error,
    Offline
};

// 文件名：与类名一致
// RecipeManager.h / RecipeManager.cpp
// TcpWorker.h / TcpWorker.cpp
```

#### Qt命名规范

```cpp
// Qt类：Q前缀
class QTcpSocket;
class QThread;

// 信号：动词过去式
signals:
    void connected();
    void disconnected();
    void dataReceived(const QByteArray& data);
    void errorOccurred(const QString& error);

// 槽：on前缀 + 对象名 + 信号名
private slots:
    void onSocketConnected();
    void onSocketDisconnected();
    void onDataReceived();
```

#### 命名原则

✅ **好的命名**：
```cpp
// 清晰表达意图
bool isRecipeValid(const Recipe& recipe);
int calculateTotalSteps(const Recipe& recipe);
void sendRecipeToDevice(int deviceId, const Recipe& recipe);

// 避免缩写（除非是通用缩写）
std::string httpUrl;  // OK: HTTP是通用缩写
int maxCount;         // OK: max是通用缩写
```

❌ **不好的命名**：
```cpp
// 过于简短，意义不明
void proc();
int n;
bool f;

// 无意义的命名
void doStuff();
int data1, data2;

// 匈牙利命名法（过时）
int iCount;
std::string strName;
```

### 1.2 代码风格

#### 缩进与格式

```cpp
// 使用4个空格缩进（不用Tab）
class RecipeManager {
public:
    RecipeManager() {
        // 4空格
        if (condition) {
            // 8空格
            doSomething();
        }
    }
};

// 大括号：K&R风格（推荐）或Allman风格
// K&R: 左括号不换行
void function() {
    // ...
}

// Allman: 左括号换行（项目可选）
void function()
{
    // ...
}

// 行宽：80-120字符（推荐100）
// 过长的行要换行
void longFunctionName(
    const std::string& parameter1,
    const std::string& parameter2,
    int parameter3) {
    // ...
}
```

#### 空格与空行

```cpp
// 运算符两边加空格
int result = a + b * c;
bool flag = (x > 0) && (y < 10);

// 逗号后加空格
function(arg1, arg2, arg3);

// 关键字后加空格
if (condition) { }
for (int i = 0; i < n; ++i) { }
while (running) { }

// 函数间空一行
void function1() {
    // ...
}

void function2() {
    // ...
}

// 逻辑块间空一行
void complexFunction() {
    // 初始化
    int x = 0;
    int y = 0;

    // 处理逻辑
    if (x > 0) {
        y = x * 2;
    }

    // 返回结果
    return y;
}
```

#### 头文件包含顺序

```cpp
// RecipeManager.cpp

// 1. 对应的头文件
#include "core/RecipeManager.h"

// 2. C系统头文件
#include <cstdint>
#include <cstring>

// 3. C++标准库
#include <string>
#include <vector>
#include <memory>

// 4. 第三方库
#include <spdlog/spdlog.h>
#include <google/protobuf/message.h>

// 5. Qt头文件
#include <QObject>
#include <QString>

// 6. 项目内部头文件
#include "common/Logger.h"
#include "common/ConfigManager.h"

// 每组之间空一行
```

### 1.3 注释规范

#### Doxygen风格注释

```cpp
/**
 * @brief 配方管理器，负责配方的加载、保存和验证
 *
 * RecipeManager使用Protobuf作为序列化格式，支持从二进制数据
 * 加载配方，并提供配方验证功能。
 *
 * @note 线程安全：所有公共方法都是线程安全的
 * @warning 必须在调用loadRecipe前初始化Logger
 */
class RecipeManager {
public:
    /**
     * @brief 从二进制数据加载配方
     *
     * @param data Protobuf序列化的二进制数据
     * @return true 加载成功
     * @return false 加载失败（数据格式错误）
     *
     * @code
     * RecipeManager manager;
     * QByteArray data = loadFromFile("recipe.bin");
     * if (manager.loadRecipeFromData(data)) {
     *     qDebug() << "Recipe loaded successfully";
     * }
     * @endcode
     */
    bool loadRecipeFromData(const QByteArray& data);

    /**
     * @brief 获取配方的序列化数据
     *
     * @param recipeId 配方ID
     * @return QByteArray 序列化后的二进制数据，失败返回空
     *
     * @throws std::invalid_argument 如果recipeId不存在
     */
    QByteArray getSerializedRecipe(int recipeId) const;

private:
    std::map<int, Recipe> recipes_;  ///< 配方存储（ID -> Recipe）
    mutable std::mutex mutex_;       ///< 保护recipes_的互斥锁
};
```

## 第二部分：版本控制规范

### 2.1 Git工作流（Git Flow简化版）

```
main (主分支)
    ├─ develop (开发分支)
    │   ├─ feature/recipe-crud (功能分支)
    │   ├─ feature/mes-gateway (功能分支)
    │   └─ bugfix/tcp-leak (修复分支)
    └─ hotfix/critical-bug (紧急修复)
```

#### 分支命名规范

```bash
# 功能分支
feature/recipe-manager
feature/qml-ui
feature/mes-protocol

# 修复分支
bugfix/memory-leak
bugfix/tcp-disconnect

# 紧急修复
hotfix/crash-on-startup

# 发布分支
release/v1.0.0
release/v1.1.0
```

#### 分支操作流程

```bash
# 1. 创建功能分支
git checkout develop
git pull origin develop
git checkout -b feature/recipe-crud

# 2. 开发并提交
git add src/core/RecipeManager.cpp
git commit -m "feat(core): implement recipe CRUD operations"

# 3. 推送到远程
git push -u origin feature/recipe-crud

# 4. 创建Pull Request
# 在GitHub/GitLab上创建PR: feature/recipe-crud -> develop

# 5. 代码审查通过后合并
git checkout develop
git merge --no-ff feature/recipe-crud
git push origin develop

# 6. 删除功能分支
git branch -d feature/recipe-crud
git push origin --delete feature/recipe-crud
```

### 2.2 提交规范（Conventional Commits）

#### 提交消息格式

```
<type>(<scope>): <subject>

<body>

<footer>
```

#### Type类型

```bash
feat:     新功能
fix:      修复bug
docs:     文档更新
style:    代码格式（不影响功能）
refactor: 重构（不是新功能也不是修复）
perf:     性能优化
test:     测试相关
build:    构建系统或依赖更新
ci:       CI配置更新
chore:    其他杂项
```

#### 示例

```bash
# 好的提交消息
feat(core): add recipe validation logic

Implement validation for recipe steps:
- Check step order is sequential
- Validate parameter ranges
- Ensure required fields are present

Closes #123

# 简短提交
fix(gateway): resolve TCP connection leak

# 破坏性变更
feat(api)!: change recipe ID from int to string

BREAKING CHANGE: Recipe ID type changed from int to string.
Migration guide: convert existing IDs using std::to_string()

# 多文件提交
refactor(core): extract protocol handling to separate class

- Move protocol parsing from TcpWorker to Protocol class
- Add unit tests for protocol parsing
- Update documentation
```

#### 提交原则

✅ **好的提交**：
- 原子性：一个提交只做一件事
- 完整性：提交后代码能编译运行
- 清晰性：消息清楚描述改动

❌ **不好的提交**：
```bash
# 过于笼统
git commit -m "update code"
git commit -m "fix bug"
git commit -m "WIP"

# 一次提交做太多事
git commit -m "add feature A, fix bug B, refactor C"
```

### 2.3 代码审查（Code Review）

#### 审查清单

**功能性**：
- [ ] 代码实现了需求的功能
- [ ] 边界条件处理正确
- [ ] 错误处理完善

**代码质量**：
- [ ] 命名清晰易懂
- [ ] 逻辑简洁，无冗余代码
- [ ] 符合项目代码风格
- [ ] 注释充分且准确

**安全性**：
- [ ] 无内存泄漏
- [ ] 无缓冲区溢出
- [ ] 输入验证充分
- [ ] 无SQL注入/命令注入风险

**性能**：
- [ ] 无明显性能问题
- [ ] 算法复杂度合理
- [ ] 资源使用合理

**测试**：
- [ ] 有对应的单元测试
- [ ] 测试覆盖主要路径
- [ ] 测试通过

#### 审查流程

```bash
# 1. 创建Pull Request
# 标题：feat(core): implement recipe manager
# 描述：详细说明改动内容、测试情况

# 2. 自动检查
# - CI构建通过
# - 单元测试通过
# - 代码覆盖率达标
# - 静态分析无严重问题

# 3. 人工审查
# - 至少1人审查（小改动）
# - 至少2人审查（重要改动）

# 4. 修改反馈
# - 审查者提出问题
# - 作者修改并推送新提交
# - 审查者确认修改

# 5. 合并
# - 所有审查者批准
# - 合并到目标分支
```

#### 审查评论示例

```markdown
# 建设性评论
**建议**：这里可以用std::make_unique代替new，更安全。
```cpp
// 当前代码
Device* device = new Device();

// 建议改为
auto device = std::make_unique<Device>();
```

**问题**：这个函数在多线程环境下不安全，需要加锁。

**优点**：粘包处理逻辑很清晰，注释也很详细！👍

**疑问**：为什么这里要用QueuedConnection而不是DirectConnection？
```

### 3.2 设计文档模板

```markdown
# 设计文档：MES网关

## 1. 架构设计

### 1.1 类图
```
MesGateway (QTcpServer)
    ├─ TcpWorker (QObject)
    │   └─ QTcpSocket
    └─ Protocol (静态工具类)
```

### 1.2 时序图
```
Client -> MesGateway: 连接请求
MesGateway -> TcpWorker: 创建Worker
TcpWorker -> QThread: moveToThread
QThread: 启动
TcpWorker -> QTcpSocket: 接收数据
TcpWorker -> Protocol: 解析协议
TcpWorker -> MesGateway: 发送信号(dataReceived)
```

## 2. 接口设计

### 2.1 公共接口
```cpp
class MesGateway : public QTcpServer {
public:
    bool startServer(quint16 port);
    void stopServer();

signals:
    void dataReceived(const QByteArray& data);
    void clientConnected(const QString& address);
};
```

## 3. 数据结构

### 3.1 协议格式
```
+--------+--------+-------------+
| Magic  | Length | Payload     |
| 4 byte | 4 byte | Length byte |
+--------+--------+-------------+
```

## 4. 错误处理
- 魔数错误：清空缓冲区，记录日志
- 连接断开：清理资源，通知上层

## 5. 性能考虑
- 每个连接独立线程，避免阻塞
- 缓冲区预分配，减少内存分配
```

    - uses: actions/checkout@v2

    - name: Setup vcpkg

    - name: Install dependencies

        .\vcpkg\vcpkg install protobuf:x64-windows

    - name: Configure CMake
