## 🏗️ 架构分层说明

### 1. 表现层 (Presentation Layer)
```
qml/
├── Main.qml              # 主界面
├── components/           # UI组件
└── views/                # 视图页面
```

**职责**：
- 用户界面展示
- 用户交互处理
- 数据绑定与显示

---

### 2. 控制层 (Controller Layer)
```
include/controller/
src/controller/
├── MainController        # 总控制器
├── RecipeController      # 配方业务控制
└── DeviceController      # 设备业务控制
```

**职责**：
- 协调各层交互
- 业务流程编排
- 信号槽连接管理

---

### 3. 业务层 (Business Layer)
```
include/core/
src/core/
├── RecipeManager         # 配方业务逻辑
├── DeviceManager         # 设备业务逻辑
├── UserManager           # 用户业务逻辑
└── StateMachine          # 状态机管理
```

**职责**：
- 核心业务逻辑
- 业务规则验证
- 领域模型管理

---

### 4. 数据访问层 (Data Access Layer)
```
include/database/
src/database/
├── DatabaseManager       # 数据库管理
├── ConnectionPool        # 连接池
├── RecipeDao            # 配方数据访问
├── DeviceDao            # 设备数据访问
└── Transaction          # 事务管理
```

**职责**：
- 数据库CRUD操作
- 事务管理
- 数据持久化

---

### 5. 网关层 (Gateway Layer)
```
include/gateway/
src/gateway/
├── MesGateway           # MES系统网关
├── SecsGemGateway       # SECS/GEM协议网关
└── RestApiGateway       # REST API网关
```

**职责**：
- 外部系统集成
- 协议转换
- 网络通信

---

### 6. 基础设施层 (Infrastructure Layer)

```
include/common/
src/common/
```

## 🗂️ CMake构建结构

```cmake
# 顶层CMakeLists.txt
cmake_minimum_required(VERSION 3.30)
project(SemiconductorRecipeManager VERSION 1.0.0)

# 全局配置
set(CMAKE_CXX_STANDARD 17)
set(CMAKE_AUTOMOC ON)
set(CMAKE_AUTORCC ON)

# 查找依赖
find_package(Qt5 REQUIRED COMPONENTS Core Gui Quick Network)
find_package(protobuf CONFIG REQUIRED)
find_package(libpqxx CONFIG REQUIRED)

# 包含子目录
add_subdirectory(proto)
add_subdirectory(src)
add_subdirectory(tests)

# 子目录CMakeLists.txt结构
src/
├── CMakeLists.txt           # 总配置
├── common/CMakeLists.txt    # common_lib
├── database/CMakeLists.txt  # database_lib
├── core/CMakeLists.txt      # core_lib
├── gateway/CMakeLists.txt   # gateway_lib
├── controller/CMakeLists.txt # controller_lib
└── app/CMakeLists.txt       # 可执行文件
```

## 📦 依赖关系

```
app (可执行文件)
 ├─> controller_lib
 │    ├─> core_lib
 │    │    ├─> database_lib
 │    │    │    ├─> common_lib
 │    │    │    └─> libpqxx
 │    │    └─> protobuf
 │    └─> gateway_lib
 │         ├─> common_lib
 │         └─> Qt5::Network
 └─> Qt5::Quick
```

**依赖原则**：
- 高层依赖低层
- 同层不相互依赖
- 避免循环依赖

## 🎯 模块职责矩阵

| 模块 | 职责 | 依赖 | 被依赖 |
|------|------|------|--------|
| common | 基础设施 | spdlog, toml++ | 所有模块 |
| database | 数据访问 | libpqxx, common | core |
| core | 业务逻辑 | database, protobuf | controller |
| gateway | 网络通信 | Qt Network, common | controller |
| controller | 流程协调 | core, gateway | app |
| app | 应用入口 | controller, Qt Quick | 无 |

## 🚀 构建与部署

### 开发环境构建

```bash
# 1. 安装依赖
vcpkg install protobuf:x64-windows
vcpkg install libpqxx:x64-windows
vcpkg install gtest:x64-windows

# 2. 配置CMake
cmake -B build -S . -DCMAKE_TOOLCHAIN_FILE=path/to/vcpkg.cmake

# 3. 编译
cmake --build build --config Release

# 4. 运行测试
cd build
```

## 🎓 学习建议

1. **自顶向下理解**：从app入口开始，逐层向下理解
2. **自底向上实现**：从common层开始，逐层向上实现
3. **模块化思维**：每个模块独立开发和测试
4. **接口优先**：先设计接口，再实现细节

---

**记住**：好的架构是演进出来的，不要追求一开始就完美，在实践中不断优化！
